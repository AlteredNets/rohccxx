# ROHC Standards Compliance Matrix

This matrix tracks the current `rohccxx` implementation against the standards we are targeting. It is intentionally conservative: a row is marked complete only when the behavior is implemented and covered by tests, deterministic generated corpora, or rohc-lib interoperability checks where rohc-lib can validate the profile. See `docs/rohc_standards_roadmap.md` for the responsibility split between the core library and PPP, lower-layer, IKEv2, or IPsec adapters. See `docs/rfc_traceability_matrix.md` for the active MUST/SHOULD/MAY traceability worklist and `docs/rfc5225_exhaustive_grammar_plan.md` for the stricter every-variant RFC 5225 closeout plan. See `docs/lower_layer_assisted_contract.md` for the RFC 3243/RFC 3408/RFC 3409 assisting-layer contract and `docs/ppp_adapter_contract.md` for the RFC 3241 PPP adapter seam. RFC 3242 is intentionally omitted from active compliance tracking because it is obsoleted by RFC 4362; profile `0x0005` is treated only as the RFC 4362 lower-layer-assisted profile identifier.

## Target Standards

| RFC | Scope | Current status |
| --- | --- | --- |
| RFC 5225 | ROHCv2 profiles for RTP/UDP/IP, RTP/UDP-Lite/IP, UDP/IP, UDP-Lite/IP, IP, and ESP/IP | Complete for the in-tree library scope: IPv4 and IPv6 compressed profile round trips are covered for RTP/UDP/IP, UDP/IP, ESP/IP, IP-only, RTP/UDP-Lite/IP, and UDP-Lite/IP; deterministic byte traces, formal CO corpora, CRC mutations, CID boundaries, feedback/mode cross-products, extension/list handling, and public C profile capability helpers cover the supported ROHCv2 profile set. Optional third-party oracle hooks are available for users who want independent corroboration. |
| RFC 3241 | ROHC over PPP | Complete at the adapter-seam helper boundary: installed public C helpers parse, write, validate, and merge ROHC IPCP option payloads plus expose PPP small/large CID protocol demux constants; source-tree C++ helpers cover internal adapters/tests; PPP LCP/IPCP/IPV6CP negotiation, framing, retransmission, and driver behavior remain outside this library. |
| RFC 3243 | Requirements and assumptions for 0-byte IP/UDP/RTP compression | Complete at conformance-helper boundary: `rohccxx` validates lower-layer packet identification, ordering, loss indication, residual error indication, feedback delivery, IPv4/UDP/RTP applicability, disabled UDP checksum, RTP sequence behavior, compressor-side ordering, and synchronized timing before allowing no-header packet use; a dedicated RFC 3243 conformance test library covers independent and aggregate missing-bit behavior; the lower layer still owns the real signals. |
| RFC 3408 | Zero-byte support for R-mode in extended LLA ROHC | Complete at the library/assisting-layer boundary: installed public C gates validate RFC 3243 assumptions plus reliable-mode, ACK, and STATIC-NACK delivery support, and RFC 4362 NHP emission now follows ACK and STATIC-NACK progression. The lower layer still owns the real ACK/STATIC-NACK signal delivery. |
| RFC 3409 | Lower-layer guidelines for robust RTP/UDP/IP compression | Complete at the adapter-contract boundary: installed public C missing-bit validators cover packet identification, ordering, loss/error reporting, feedback delivery, context-packet protection, CSP support, and CCP support before RFC 4362 context packets are enabled. |
| RFC 4362 | Link-layer-assisted IP/UDP/RTP profile | Runtime API support complete at the library/assisting-layer boundary: profile ID 0x0005, explicit opt-in contract gates, NHP emission/reconstruction, large-CID assisted NHP/CCP dispatch, CSP synchronization, CCP verification, R-mode ACK/STATIC-NACK NHP gating, source-tree native C++ wrappers, generated external-oracle corpus, loss/residual-error signals, parser visibility, and negative ordinary-decompressor gates are covered. Link-specific scheduling and packet identification remain adapter-owned. |
| RFC 5795 | ROHC framework, channels, context handling, feedback, segmentation, CRC behavior | Complete for current library boundary: context lifecycle, CRC checks, NACK path, small feedback packet formatting/parsing, opt-in segmentation/reassembly, and first-class uncompressed profile behavior are covered; future debt is limited to channel policy required by embedding stacks |
| RFC 5856 | ROHC over IPsec architecture | Complete for library/adapter boundary: channel parameters, implicit LARGE_CIDS, feedback linkage metadata, ROHCoIPsec SA data, KEYMAT directional key provisioning, and compressor/decompressor SA application are covered. Actual SPD/SAD ownership remains with the embedding IPsec stack. |
| RFC 5857 | IKEv2 negotiation for ROHC over IPsec | Complete for library/adapter boundary: ROHC_SUPPORTED attributes are encoded/decoded for MAX_CID, ROHC_PROFILE, ROHC_INTEG, ROHC_ICV_LEN, and MRRU; duplicate, unsupported, and incoherent profile/integrity/ICV combinations are rejected; negotiated channel parameters can build ROHCoIPsec SA state and consume directional KEYMAT. Full IKEv2 message exchange remains with the embedding IKEv2 implementation. |
| RFC 5858 | IPsec processing extensions for ROHC packets, integrity, and ordering | Complete for library/adapter boundary: ROHC protocol number 142, NONE integrity with zero ICV, HMAC-SHA-256 truncated ICV append/verify with non-zero bounded ICV lengths, AH/ESP Next Header helper decisions, SA application, and compressor/decompressor processing order are covered. Kernel/user-space AH/ESP packet ownership remains with the embedding IPsec stack. |

| RTP/UDP/IP | 0x0101 | Complete for in-tree RFC 5225 profile grammar | IPv4 RTP packets cover IR, IR-DYN, FO, formal CO variants, large-CID RTP FO, CRC rejection, deterministic byte-trace parity, and rohc-lib RTP interop traces; IPv6 round-trip and trace-fingerprint coverage is included. |
| UDP/IP | 0x0102 | Complete for in-tree RFC 5225 profile grammar | Classifier recognizes IPv4/UDP without RTP; compressed IR, IR-DYN, FO, and applicable formal CO variants encode/decode round-trip; deterministic byte-trace parity is pinned for the current wire grammar. |
| ESP/IP | 0x0103 | Complete for in-tree RFC 5225 profile grammar | Classifier recognizes ESP; compressed IR, IR-DYN, FO, and applicable formal CO variants encode/decode round-trip; deterministic byte-trace parity is pinned for the current wire grammar; ROHCoIPsec behavior remains separate. |

## Release Maintenance Notes

1. Keep deterministic profile parity fixtures current whenever the intentional wire grammar changes.
2. Keep generated negative, CRC, CID, and buffer-limit cases synchronized with future packet-family additions.
3. Use `docs/external_oracle.md` and the optional `ROHCCXX_*_ORACLE` hooks only when a compatible third-party implementation is available; the in-repo corpus remains the primary release gate.
4. Treat ROHCoIPsec as complete at the `rohccxx` library boundary. `docs/embedding_stack_integration.md` defines the adapter contract for IKEv2 exchanges and AH/ESP SPD/SAD packet ownership; optional additional integrity transforms can be added if negotiated by a deployment.

# RFC 5225 Conformance Matrix

This matrix tracks ROHCv2 profile work at a finer granularity than the high-level RFC compliance summary. A profile parity slice is complete when classification, packet grammar, encoder bytes, decoder replay, and negative mutation tests are all pinned; rohc-lib comparison is retained where rohc-lib can validate the target profile version. For the stricter definition where RFC 5225 compliance means every possible packet grammar and encoding variant, use `docs/rfc5225_exhaustive_grammar_plan.md` as the closeout checklist. The machine-readable manifest foundation is tracked in `docs/rfc5225_packet_grammar_manifest.md` and generated by `interop_rfc5225_grammar_corpus`.

## rohc-lib Oracle Notes

The pinned rohc-lib submodule is a mandatory bidirectional external oracle for deterministic three-packet IPv4, small-CID-0, no-IP-options flows in the RFC 5225 RTP/UDP/IP, UDP/IP, ESP/IP, and IP-only profiles. The tests require exact reconstruction in both directions; they do not externally validate IPv6, other CID forms, IP options, or extension-header chains. rohc-lib does not provide compatible RFC 5225 UDP-Lite profiles, so RTP/UDP-Lite/IP and UDP-Lite/IP retain internal coverage without an external interoperability claim. The optional RFC 4362 hook is unchanged.

## Near-Term Acceptance Gates

1. A profile may move from `Fallback round-trip` to `Compressed encoder` only with unit coverage for first-packet, refresh, compressed steady-state, malformed input behavior, and mode/feedback behavior when the profile changes state.
2. Current compressed profile parity requires deterministic encoder byte fixtures, decoder replay from those fixtures, and negative mutation coverage; external rohc-lib parity remains required only for profile versions rohc-lib can actually validate.
3. RFC 5856, RFC 5857, and RFC 5858 work stays outside this RFC 5225 profile matrix. The core now has tested ROHCoIPsec channel-parameter negotiation helpers, SA/KEYMAT adapter seams, RFC 5858 protocol-number identification, NONE and HMAC-SHA-256 ICV handling, AH/ESP Next Header routing helpers, and enabled compressor/decompressor processing order; real IKEv2 exchanges and AH/ESP SPD/SAD packet ownership remain embedding-adapter responsibilities.

## Encoding Method Notes

The current encoding-method layer is complete for the implemented packet grammar. It covers reusable W-LSB extraction/min-width helpers, profile-field LSB variants, RTP FO sequence LSB emission, scaled RTP timestamp stride inference from IR to IR-DYN, timer-scaled RTP FO decode integration, offset IP-ID helpers, reusable SDVL helpers, empty-list marker handling, generic and profile-specific extension-list encode/decode primitives, typed IPv6 extension-header metadata parsing, explicit unsupported dynamic-list rejection, and regular 160-clock RTP FO parity. New encoding variants should be added with the future packet families that require them.
